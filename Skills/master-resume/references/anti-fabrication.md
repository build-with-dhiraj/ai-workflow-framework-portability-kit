# Anti-Fabrication & Provenance Discipline

The primary defense against both dishonesty and AI-detection is **specific, real facts**. This file keeps every claim true. Read before generation and before every edit.

## The three hard rules
1. **No invented facts.** Never create a metric, title, date, employer, degree, or publication that isn't in the library. If it's not there, it doesn't go on the resume.
2. **No status inflation.** Under-review ≠ published. Contributed-to ≠ led. A course project ≠ production. Reframing adjusts emphasis, never truth.
3. **Verify before claiming.** Every quantitative claim traces to a library entry. Numbers the user couldn't confirm stay off the page (mark `unverified` in the library).

## Provenance flags → allowed language

| Status | Allowed on the page |
|---|---|
| `published` | Cite venue; specific numbers OK |
| `under-review` | "under review at [Journal]" — never "published" |
| `preprint` | Flag as preprint (arXiv/bioRxiv/etc.) |
| `internal` / `proprietary` | "infrastructure I developed" — no external/peer-reviewed metrics |
| `unpublished` | No specific result numbers, no publication claim |
| `team` | Contributing-author verbs only (below) |

## Verb discipline

**Full-ownership verbs** (only where the candidate personally owned the work):
built, designed, led, shipped, architected, created, founded, drove, owned.

**Contributing verbs** (team work where the candidate was one of several):
contributed to, supported, co-developed, helped, collaborated on, assisted with.

Match the verb to the verb-ownership level stored on the library bullet. A first-author paper earns "led/developed"; a 5th-author paper earns "contributed to."

## Truthfulness audit (run in critique Part 5 too)
For each bullet: `claim → verified against library? → source id`. Any unverifiable claim is cut or softened before the resume is shown.

## Domain-gap honesty
When the candidate is transitioning, the resume should be transparent about the actual domain while showing what transfers. Honest reframing ("the same MD-simulation methodology applies to…") beats pretend expertise — and it survives the interview. Pretend expertise fails the technical screen.

## Corrections log
Keep a Corrections section in `config.md`. Every correction the user makes (wrong metric, title, date, attribution) is logged and checked before every future generation so the error never returns. See [knowledge-base.md](knowledge-base.md).
